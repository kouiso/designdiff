# Changelog

All notable changes to this project are documented in this file.

The format is based on Keep a Changelog, and this project follows Semantic Versioning.

## [Unreleased]

### Added

- The Figma plugin can send the selected frame to the Chrome extension overlay. Set the implementation page as the extension target first; the handoff now exports the selected frame, routes it to that saved tab, and reports success or a retryable error in the plugin. A missing or silent extension is reported after the request timeout instead of leaving the plugin stuck on "Sending". The extension popup also loads the handed-off design image and frame size from the target tab's overlay, so Capture & Compare works from the handoff without a Figma REST token.
- `compare_design_batch` MCP tool (`app/mcp-server/src/tool/compare-design-batch.ts`): compares 1-10 frames/screens sequentially in one call through the existing `compare_design` engine and returns per-frame verdicts (`PASS` / `FAIL` / `UNCERTAIN` / `ERROR`) plus an aggregate report — counts, aggregate `verdict` (`ERROR > FAIL > UNCERTAIN > PASS`), `comparisonIds` for full `generate_diff_report` retrieval, `recurringIssues` (issue kinds seen in two or more frames), and a flow-level `convergence` folded from each frame's `loopGuard`. A per-frame execution failure is reported as `ERROR` and does not abort the remaining frames; shared `threshold`/`profile`/`design_background`/`ignore_regions`/`anchors` defaults are overridable per frame (frame value replaces the default, no merge). Aggregation lives in `app/mcp-server/src/service/batch-compare-service.ts`.
- Electron IPC smoke test (`app/desktop/e2e/electron-ipc-smoke.mjs`): launches the real Electron binary and drives `project`, `token`, and `file:read-local-image` IPC paths; wired into CI on xvfb.
- CI jobs for the Figma-plugin host E2E (`real-iframe-host.mjs`) and Chrome-extension E2E (`real-chrome-e2e.mjs`), both previously local-only scripts.
- Crop-region round-trip integration coverage (`set_crop_region` → `compare_design` auto-application → `get_crop_region`) and Figma-plugin message-contract tests (requestId echo, `figma.command` menu routing).
- `script/eval/figdiff-perf-bench.mjs`: p50/p95 wall-clock bench for `compareImages` across SP/PC/tall profiles, with per-profile p95 gates (`FIGDIFF_PERF_P95_MS[_<PROFILE>]`); results recorded in `docs/evidence/perf-bench.json` and the threshold decision in `docs/perf-bench.md`.
- `compare_design` with `rasterization_tolerance` now reports how far proven same-token content moved (`sameTokenRasterization.contentOffset`) and emits a `same_token_content_offset` position issue (minor from 1.5px, major from 3.5px). Offsets that hit the ±4px search bound are reported as a lower bound (`clipped`, sign-aware). Estimates that window data cannot disambiguate — a second aliased correlation peak or strongly periodic content — are marked `ambiguous` and emit no issue. The verdict is unchanged; shifted text or icons no longer pass silently.
- `docs/acceptance-matrix.md`: per-feature acceptance table (expected behavior, pass criteria, verification, latest evidence) covering all MCP tools, desktop, extension, and plugin surfaces.
- CI workflow `.github/workflows/device-legs.yml` runs the mobile capture verification legs on GitHub-hosted runners and uploads per-round evidence as artifacts: `stdio-android-verification.mjs` (X05/X07) twice per run on KVM-accelerated `ubuntu-latest` Android emulators (API 30 and API 34, `google_apis` x86_64) and on a `macos-15-intel` Android host probe, plus `stdio-ios-sim-verification.mjs` (X06 via the accepted iOS Simulator substitute) twice per run on `macos-15`. Runner host, emulator, and swipe-latency records are captured so each artifact states its host truthfully (emulator/simulator, never a physical device). The physical-iPhone `ios-device` leg of X06 cannot run on CI.

### Fixed

- `compare_design` with a local PNG design (no Figma node tree) no longer passes a screen while ignoring real differences. It used to score only the 24 largest pixel-diff clusters and silently drop the rest, so a small icon color change or a missing glyph past the 24th cluster never reached the verdict. Up to 200 clusters are now scored, the same limit the Figma URL path already used. If more than 200 remain, the comparison returns `UNCERTAIN` (inconclusive) instead of `PASS`, because the unscored clusters were never measured. Screens whose differences were all in the top 24 clusters, and every Figma URL comparison, keep the same verdict.
- `compare_design` no longer reads as a clean PASS in its human-readable summary when every difference is under the pixelmatch `threshold` (for example a shadow blur radius change). The `subThresholdDiffPixelCount` warning used to appear only in the JSON `suggestion`, while the summary said 差分はほぼありません. The summary now shows the sub-threshold pixel count, its share of the scored pixels, and the low-amplitude warning. The field is now counted by re-running pixelmatch at `threshold: 0` instead of comparing raw channel values, and is only returned when `diffPixelCount` is 0, so it always means "pixels a lower threshold would count" — anti-aliasing pixels that even `threshold: 0` will not count no longer inflate it. Its summary guidance follows the ループ判定: 続行 suggests re-running with a lower `threshold`, while 停止 asks the agent to report the warning to a human instead of calling the tool again. `status`, `diffPixelCount`, and the default threshold are unchanged. The field is now listed in the tool description and `docs/api/mcp-tools.md`.
- The `compare_design` summary line 構造SSIM判定 no longer prints the raw internal verdict token alone (for example INCONCLUSIVE in the middle of Japanese text, unreadable for non-developers). The line now reads 構造差なし (PASS) / 構造差あり (FAIL) / 判定不能 (INCONCLUSIVE), Japanese first with the machine-readable token kept in parentheses. The pass and fail labels describe only the structural difference, because the overall `status` can still be `FAIL` or `UNCERTAIN` when the structural verdict passes (token or anchor violations, suspected misconfiguration); completion is decided by `status` and the ループ判定 line. The inconclusive case, which always yields `UNCERTAIN`, states on the line itself that it is not a failure and should be reported to a human rather than "fixed".
- Figma URL comparisons now export the selected node's own background by default instead of `contents_only`, which strips frame fills and can create false color failures when a transparent export is flattened over white; `contents_only: false` also renders content that overlaps the node (Figma's documented semantics), so pass `true` when such overlaps must stay out of the reference. With `figma_contents_only: true` and no `design_background`, fully transparent design pixels inside the composed design content are excluded from scoring while semi-transparent edges remain included; contain-resize canvas gaps are not, and local PNG transparency is still composited over white so intentional transparent holes stay scored. A comparison left with no scorable pixels — a fully transparent design, or a fully transparent design whose contain-resize letterbox is the only unmasked area — returns `UNCERTAIN` rather than a false `PASS`. With `rasterization_tolerance`, a section no longer fails on a broad average when every intersecting pixel-diff cluster has a passing local proof and no perceptible difference remains outside the accounted cluster boxes; unexplained clusters, clusters dropped by the scoring cap or by the clustering threshold, and perceptible differences outside the accounted boxes still fail. `verify_fix` now replays the recorded background semantics (explicit colour vs omitted) instead of collapsing both to white; a baseline recorded before this change replays as omitted (local-PNG scoring is the same either way), and one that used an explicit background rejects the automatic replay and asks for the same `design_background` value the baseline used.
- `compare_design` with `rasterization_tolerance` no longer fails a screen because a 1-5px-thin border, divider, or card edge was drawn 1-3px away from the design. These used to surface as critical `flat_region_color` / `delta_e_2000` issues ("the fill is #FFFFFF instead of #CCEBD8"). Such regions now carry a `localDisplacement` proof and a minor `local_displacement` position issue with the measured offset. The proof compares a window widened by the shift range, so an element present on only one side (a caret or line at a different place), a recolored line, or a shift beyond 3px still fails. A line that also carries a uniform token step small enough to stay under the ΔE threshold (e.g. `#D9D9D9` → `#DBD9D9`) is not relieved either: the proof records `alignedTokenMatch`, and a residual uniform step keeps the color issue critical, while ±1 dither and scattered AA residuals remain relieved. Without `rasterization_tolerance` the verdict is unchanged.
- MCP tool and desktop Figma errors now match the live Figma API's actual failure modes, measured against `api.figma.com` with real PATs. `FigmaClient.fetchApi` (`package/shared/src/figma-client.ts`) replaced 401/403 response bodies with assumed fixed text, so an expired PAT on the file endpoints — which Figma answers with `403 {"err":"Token expired"}` — was reported as "Access denied (403). You don't have permission to access this Figma file", sending the user to check file sharing instead of regenerating the token. Non-OK responses now carry the real body in `FigmaApiError` (as 404 and other statuses already did), `isTokenError` recognizes the live expiry texts (`Token expired`, `Token has expired`) so the desktop still routes them to token re-entry, and the MCP error classifier (`app/mcp-server/src/tool/error.ts`) classifies a 403 whose body says the token expired as an authentication failure. A `404 {"err":"Not found"}` from a valid token whose account cannot see the file was collapsed to "Figma API request failed. Check the request and retry." even though the request was well-formed; the raw Figma error body is now surfaced for the allowlisted body shape (matching `get_design_tokens`, which already returned it), while secret-bearing or non-allowlisted messages are still reduced to fixed text.
- Chrome extension popup: `Capture & Compare` failures (for example `captureVisibleTab` blocked without `activeTab`) are now shown as an actionable error on the Upload tab instead of being silently swallowed; the button shows a `Comparing...` state while running and is re-enabled for retry, and `real-chrome-e2e.mjs` now fails on any invisible compare outcome instead of recording `no-visible-result`.
- `report_issue` context footer now reads the figdiff version from `app/mcp-server/package.json` at runtime instead of the hardcoded `0.1.0`, falling back to `unknown` when the package metadata is unreadable.
- `sameTokenRasterization.contentOffset` no longer reports confident offsets it cannot verify. A periodicity scan that could not run — the FFT cell cap on very large windows, or a window with ignore regions where the FFT path cannot honor the mask — now marks the estimate `ambiguous` with the reason in `periodicityUnchecked` (`fft-window-too-large` / `fft-masked-window`) instead of silently claiming "no periodicity"; the measured `dx`/`dy`/`peak` stay in the evidence for review, and no `same_token_content_offset` issue is emitted.
- `contentOffset.peak`, `dx`, and `dy` are now reported as raw (unrounded) values so the report-side confidence floor (0.8) and the 1.5/3.5px magnitude thresholds are decided on the measurement itself; a raw peak of 0.798 no longer rounds to 0.8 and fires a position issue. Rounding is applied only to the human-readable issue text.
- The FFT self-NCC plane for large windows validates dimensions, search spans, and the cell cap before allocating anything (previously a window beyond the cap allocated an all-NaN plane of roughly the window's area first), and returns an explicit "unmeasurable" result instead of a NaN plane.
- Correlation candidates for `contentOffset` now require a minimum number of ink-bearing pixel pairs instead of just any four overlapping pixels, so a single coinciding dot between two otherwise-blank windows can no longer produce a perfect (1.0) correlation reported as a clipped translation.

## [2.0.0] - 2026-04-18

### Added

- Added the `DiffReport` type with `aggregateVerdict`, `regionScores`, `issues`, `alignment`, `weightedAggregate`, and `rationale`, defined in `package/shared/src/type.ts` and validated by `package/shared/src/schema.ts`.
- Added SSIM computation based on BT.601 luminance with an `8x8` box window in `package/shared/src/signal/ssim.ts`.
- Added multi-region SSIM scoring with optional `figmaNodeId` links per region in `app/mcp-server/src/service/diff-report-builder.ts`.
- Added an area-weighted aggregate verdict pipeline through `computeVerdict` in `package/shared/src/type.ts`.
- Added golden fixture coverage for `pair-01-simple-static-lp` and `pair-02-multi-section-lp` in `app/mcp-server/src/service/fixture-runner.test.ts`.

### Changed

- Changed the `compare_design` MCP tool to return `structuredContent` parsed with `CompareDesignResultSchema`, including `diffReport`, in `app/mcp-server/src/tool/compare-design.ts`.
- Changed `matchRate` handling so backward compatibility remains, but `diffReport.aggregateVerdict` is now the canonical pass/fail/inconclusive signal.

### Deprecated

- Deprecated workflows that rely only on `matchRate` for pass/fail decisions. Consumers should read `diffReport.aggregateVerdict` and inspect `diffReport.issues`.

### Removed

- Nothing removed in `v2.0.0`. Backward compatibility is preserved for `matchRate` consumers.
