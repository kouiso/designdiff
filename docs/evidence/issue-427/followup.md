# #427 追加検査: 重なりの原因と停止条件

本書の配送状況はPR #431作成前の記録。現在のpush・レビュー状況はPR側を参照。

## 結果

閾値・群ラベル・known RED・推定器は変更していない。全18 correct ペアを同じ独立プローブに掛けた。3件は寸法不一致、残る15件で位置・エッジ・色を測定した。追加指標でも分離できない。

| 独立診断 | pass 範囲 (9) | fail 範囲 (同寸法6) |
|---|---:|---:|
| delta>40画素のうち半径1pxのエッジに隣接する割合 | 72.6556–99.6847% | 63.8037–99.5105% |
| delta>40画素のうちRGB符号付き差の幅<=20 (概ね輝度側) | 57.2168–95.4742% | 58.4311–95.6969% |
| 行プロファイルで選んだ位置補正後の生差分率 (共通内部領域) | 1.1591–8.5290% | 2.2201–17.0532% |

位置補正は診断値のみ。全ての整数dy=-80..80で同じ内部領域(y=80..height-80)を用い、固定128px帯ごとのインク行密度(sumRGB<600)の絶対誤差を最小化した。端を切り捨てる量は候補間で同じ。選んだ位置で、独立したdelta>40のraw比較も記録。単色帯は161候補が同点になるため、同点数とraw残差を併記し、最適シフトを真の移動と即断しない。画像変更・採点への補正適用はしていない。

## 具体的な重なり

- **pass pair-22 vs fail pair-21:** 元の差分率8.8825% vs4.1004%は逆転。pair-22の原画像を直接見比べると上部の入力欄・メニュー・AI回答は約56pxずれ、下部キーボードは同じ位置。固定帯の実測はy80..208でdy=-56、raw20.4367%→4.4171%、y208..336でdy=-57、raw13.2312%→0.5248%、y336..464でdy=-56、raw6.3341%→4.8758%。y464..592はdy=0、raw=0。単純なAA/サブピクセル差では説明できない位置差を含む。
- **pass pair-09 vs fail pair-12:** pass09はy80..592の4帯すべてdy=-56。fail12も先頭3帯で-55/-53/-52。56px近傍の移動があること自体はpass/failを区別する指標ではない。変位を大きく許すと内容が変わったfail12も一部説明できてしまう。
- **fail pair-21:** 原画像では設定メニュー「単位設定」「データのエクスポート」が実装側に無い。設定パネルはその分短く、同寸法でも白余白が増える。上部は数pxのずれ、下部は行欠落を含み、帯ごとの最適変位が-4/-7/-5/-8/-6/-68と一貫しない。変位補正で画素差分を減らせても欠落の解消を意味しない。
- **pass pair-07 vs fail pair-17:** エッジ隣接率99.13% vs99.51%、輝度寄りの差分率83.37% vs95.70%。真の内容差も輪郭に発生するため、「輪郭に集中するからAA」とは判定できない。位置補正後の内部領域生差分率もpass07=8.5290%がfail21=2.2201%を上回る。
- **fail pair-13/16/24:** 寸法不一致だけは独立に検出可能。ただし他6件の同寸法failを分類する問題は残る。resizeで同寸法に見せる操作は行っていない。

エッジから遠い差分率やRGBの色差割合も群の範囲が重なる。位置・色・輪郭のいずれか一つだけを原因として解決する根拠は得られなかった。今回の指標に分離能がないことを示しており、あらゆる独立指標が数学的に不可能と主張しているわけではない。

## 必要な仕様判断

pair-22のfixture notesは「細ストロークAA/ストローク被覆差のみ」とするが、実画像は上部約56px・キーボード0pxという部分的な位置差を含む。#243の1px以下ドリフト許容と同じ条件ではない。これが撮影時のstatus bar/viewport条件差なのか実レイアウト差なのかは、PNGだけから断定できない。

次に必要なのは次のどちらかの根拠ある判断である。

1. **撮影条件を揃える:** Figma/実装のviewport・system UI・keyboard条件を照合し、同一内容の9ペアを同じ座標系で再キャプチャする。既存原本は残し、由来と変換条件を別途記録する。
2. **部分的な位置差を許容条件として明文化する:** pair22等で上部56px・keyboard0pxの対応を撮影メタデータや元レイアウトから独立に裏付け、検査前に許容変換と保護領域を固定する。最小差分になる変換を推定してpassにする方法では、fail12やfail21を吸収するため不十分。

その上で人手根拠付きの欠落行/同一グリフの対応領域を用意すれば、領域別の独立画素指標を評価できる。現在の画像・ラベルだけから「AAと内容差を分離できた」と認定するための閾値を作ることはしない。ラベルを変更する権限や撮影条件の正解根拠がないため、この仕様判断・追加原本が必要な時点で検査を止める。#427/#243は受入未達のまま。

## 検証と成果物

`probe-gate1-overlap.mjs` は新規の独立script。既存測定scriptの画像デコードだけを利用し、製品判定やfixture runnerをimportしない。20pxの既知変位をraw=0まで復元する合成画像と、単色同点/寸法/不正bufferを検査するunitを追加。元の4件と合わせ6件、Biome、ESLint、checkJs/TypeScript、生成PNG15件を最終コードで検証する。元の33variant/66比較測定も再実行して保存済み結果とbyte比較する。全検証は60秒上限、sharp concurrency1、逐次処理。

pushはAPI Forbiddenによる副作用未確認のため未試行のまま。共有アーカイブにはreport/followup、全生ログ、validation、測定JSON、全追加ソース、patch、bundle、ファイルごとのSHA256一覧を入れる。fixture PNGはコピーしない。元PNGのSHA256は測定JSONに記録済みで、指定developから検証できる。
