# Device legs: independent oracle status (PR #370)

| Leg | Independent check | Status |
|---|---|---|
| X07 Android scroll stitch | `app/mcp-server/script/lib/stripe-stitch-oracle.mjs` reads the stitched PNG's pixels (8 known colours, order, no duplicate/missing section, inner section heights) without using FigDiff's `scrollCapture` report. Wired into `stdio-android-verification.mjs` (skipped when `ANDROID_PAGE_URL` is user-supplied). | Oracle logic unit-tested on Linux with synthetic PNGs (7 cases: pass, missing, duplicated, reordered, stretched, anti-aliased boundary rows, sections that start/end dark). Sections are classified by runs of >= 8 same-colour rows, so 1-2 blended boundary rows cannot reorder the stripes. **Not yet run against a real emulator capture** — the colour distance (60) and inner-height tolerance (25%) are unmeasured on real Chrome rendering. The coloured span of the page's sections is not 800px each (measured at 1:1: 760, 800, 800, 800, 792, 720, 792, 800 because the gradient phase ends in dark), which is why the tolerance is not tighter. The stitched capture is kept in the artifact as `round-N/x07-stitched.png` (copied before the check runs, so it exists on failure too). If a real run fails here, check `evidence.json` -> `X07_android_scroll.independentStitchCheck` (`sequence`, `sectionRows`, `reasons`) before loosening anything. |
| X06 iOS Simulator capture | Compare the captured PNG against the direct `simctl io screenshot` pixels and validate the system-UI mask geometry independently. | **Pending macOS measurement.** Needs a macOS runner to decide the tolerance for regions that change between captures (status-bar clock). Only width/height equality is asserted today. |

Until the emulator run confirms the X07 thresholds and the macOS run defines the X06 comparison, these legs record that capture *works*; they are not proof that stitching or iOS pixels are correct.
