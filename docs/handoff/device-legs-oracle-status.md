# Device legs: independent oracle status (PR #370)

| Leg | Independent check | Status |
|---|---|---|
| X07 Android scroll stitch | `app/mcp-server/script/lib/stripe-stitch-oracle.mjs` reads the stitched PNG's pixels (8 known colours, order, no duplicate/missing section, inner section heights) without using FigDiff's `scrollCapture` report. Wired into `stdio-android-verification.mjs` (skipped when `ANDROID_PAGE_URL` is user-supplied). | **Ran on a real emulator** (run 38396616289, API 30): the oracle failed both rounds — stripes missing and inner section spans far off — and `x07-stitched.png` shows the stitched image compressed (~1058/1467 rows for a 6400 css px page). This is a genuine stitch defect on real Android Chrome, not an oracle threshold problem; it is tracked as its own issue instead of loosening the oracle. Rows need >=2/3 sampled columns to count as a stripe, and an absolute floor (`inner span sum >= 0.8 * 4800 * width/500`) now also rejects uniformly compressed stitches that relative checks alone would pass. The stitched capture is kept in the artifact as `round-N/x07-stitched.png` and `evidence.json` is persisted before the oracle asserts, so `X07_android_scroll.independentStitchCheck` (`sequence`, `sectionRows`, `reasons`, `measuredScale`, `toastRows`) survives failures. A transient toast-colour fixture in the page asserts zero toast rows in the stitched image, and `ignoreRegionResolution` must report non-empty regions with masked pixels. |
| X06 iOS Simulator capture | Captured PNG is compared pixel-for-pixel (sampled) against the direct `simctl io screenshot` and the system-UI mask geometry is asserted via `ignoreRegionResolution`. | Implemented: sampled pixel divergence must stay under 30% (status-bar clock jitter allowed) and `effectiveRegions` must be non-empty with `maskedPixelCount > 0`. Not yet exercised on macOS — the tolerance is set from the same reasoning as X07 and the next run records `independentPixelCheck` in evidence.json. |

The X07 oracle has produced real signal on the emulator: the stitched output is measurably broken. The current red CI reflects that defect, not oracle noise.
