# FigDiff 実利用テスト仕様書

この仕様は `implementation-plan.md` の受入条件を検証する。
単体テストの成功、起動しただけの画面、過去の証跡は実利用の合格に代用しない。

## 実行環境と記録

- macOS arm64 を優先し、Windows ネイティブと Ubuntu／WSL2 を別環境として実行する。
- iOS の実機・Simulator は macOS、Android は接続可能な各ホストで実行する。
- Node・pnpm・アプリ・ブラウザ・OSの実測バージョンと対象 Git SHA を記録する。
- 通常のユーザーデータを使わず、案件、比較履歴、ブラウザプロファイルを分離する。
- `FIGDIFF_HOME` だけで資格情報まで分離できるとは仮定しない。各保存先を確認してから起動する。
- Figma の実データ検証は既存の許可された認証で行う。キー、トークン、非公開画像は公開証跡へ含めない。
- 実装依存を避けた画像検体を用意する。元画像、操作した矩形、色、倍率、移動量が正解となる。

各実行記録には次の項目を残す。

| 項目 | 内容 |
|---|---|
| case / round / platform | 下記ID、巡回番号、OSと実行経路 |
| revision / environment | Git SHA、バージョン、ビルド対象と生成日時 |
| input / prerequisite | 入力検体、寸法、設定、認証・端末などの前提 |
| steps / expected / actual | 実行操作、期待値、実測値 |
| oracle / evidence | FigDiffから独立した判定根拠、画面・通信・ログの保存先 |
| status / issue | NOT RUN / PASS / FAIL / BLOCKED、関連Issueと失敗理由 |

`N/A` はOS固有の非対応機能だけに使い、理由を記録する。
利用できるはずの機能に前提が足りない場合は `BLOCKED` とする。
以下の初期状態はすべて **NOT RUN**。結果は `work-status.md` から実行証跡へリンクする。

## 統合ゲートと収束

1. build、check、lint、lint:eslint、typecheck、test、全package coverageを実行する。
2. Playwright、Electron本体、独立oracleの検体検査を実行する。
3. #144/#146と新規PRは対象headのCI・コードレビュー・動作証跡を確認する。
4. #79は新しいクラウドセッションで設定元と固定プロンプトの挙動を確認する。
5. #69は指定範囲・tree不変・参照・復旧手順を別記録に残す。
6. 最後の修正を含む同一SHAで、上記実利用を2巡する。各巡で新規不具合0件を確認する。
7. 修正が入ったら巡回番号をリセットする。失敗・未実行・ブロックが残る限り完了とはしない。

Windows／WSLで実行不能の項目は、失敗したコマンドと復旧後の実行手順を `handoff/windows-wsl-verification.md` に残す。
