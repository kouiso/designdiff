# FigDiff UX/UI Audit — 2026-05-16

**Scope**: `app/desktop` renderer (React 19 + Electron 35). Static code review against
`origin/develop` @ `5a6c032`. 5 main pages (home, project, compare, live-overlay, settings)
plus UI primitives.

**Method**: Direct source read of all page-level components, UI primitives, dialog/focus
logic, theme tokens, and i18n usage. Live Playwright walk was not run (the renderer is
testable on Vite dev server; this PR is audit-only and deliberately ships zero code change
so that fix PRs can be sequenced individually).

**Severity legend**:
- **Critical** — broken/unusable, WCAG AA violation, essential affordance missing.
- **High** — friction, missing error/loading/empty state, missing keyboard nav,
  important a11y gap.
- **Medium** — design-system inconsistency, drift, tone problems.
- **Low** — future debt, polish.

## Cross-cutting observations (no individual row)

- **Color tokens**: theme system in `index.css:33-84` is clean (CSS variables for light & dark). Light-mode contrast spot-checks: `--muted-fg #6b6b74` on white ≈ 4.85:1 (passes AA for normal text, fails AAA at 7:1). `--primary #6d28d9` on white ≈ 7.8:1 (AA-large pass). No critical contrast violations found at the token level.
- **Loading patterns**: single Spinner/LoadingCard/LoadingOverlay primitive — good consistency. Cancel affordance missing (see #5).
- **Empty states**: Home → strong, Compare → strong (ImageIcon + copy), Project → minimal text only, Live Overlay → weakest (see #9).
- **Icon library**: `lucide-react` used exclusively — good, no drift.
- **i18n coverage**: `useTranslation()` used throughout; no hardcoded JP/EN strings in app shell. ErrorBoundary uses `i18next.t` directly without React subscription — works but won't react to language change while in error state.

## 2.1 Ten-Persona Review Panel

Each persona gives one strongest critique tied to a specific file:line. Convergent themes drive the priority list at the end.

### Dieter Rams — *"Less but better"*
> The Compare page toolbar packs 7 view-mode icons, an opacity slider, a separator, and 3 status badges into a single horizontal strip (`app/desktop/src/component/compare/compare-page.tsx:209-280`). The user needs one — *one* — view mode at a time and the controls relevant to that mode. Hide the rest.
> **Recommendation**: collapse view-mode toggle into a segmented control with progressive disclosure: only the active mode's controls are visible. (Reinforces Part 1 #26.)

### Don Norman — *Affordance / mapping*
> `crop-region-selector.tsx:115-117` — the "Select region" button has no `onClick`. The affordance promises an action; the system delivers nothing. This is a textbook *signifier-without-mapping* failure. Worse, the actual selection mechanism (mousedown on canvas) is undiscoverable.
> **Recommendation**: see Part 1 #4. Cursor change alone is not a sufficient signifier.

### Jakob Nielsen — *Heuristic violations*
> H1 (Visibility of system status): the comparison runs as a full-screen `LoadingOverlay` with no cancel and no progress (`compare-page.tsx:199`). Users have no idea if it's still running or hung. Combine with H3 (User control and freedom): no escape from the loading state.
> **Recommendation**: see Part 1 #5. Also surfaces in 2.2 Usability score.

### Steve Krug — *"Don't make me think"*
> Home page asks the user to interpret two adjacent input cards (`home-page.tsx:108-132`) that look identical but mean different things. Cognitive load is created by the symmetry: the user must read the labels carefully to choose. Don't make me think.
> **Recommendation**: see Part 1 #28.

### Luke Wroblewski — *Forms & inputs*
> The Figma token field (`setting-dialog.tsx:128-138`, `token-required-dialog.tsx:75-88`) is `type="password"` with no reveal-once toggle, no paste affordance, no character-counter, no validation feedback until Submit. Tokens are 40+ characters — typos are likely and uncorrectable.
> **Recommendation**: combine Part 1 #22 (reveal toggle) with inline `FigmaTokenSchema.safeParse` validation on blur. Strip surrounding whitespace defensively (`tokenInput.trim()` happens at submit — too late for visual feedback).

### Frank Chimero — *Editorial taste*
> Typography is technically sound (Hiragino / Noto Sans JP stack, line-height 1.7) but the hierarchy is *too quiet*. The hero `text-4xl` heading is gradient-clipped purple-on-purple (`home-page.tsx:97`), which fights legibility. Body text and hint text are tonally indistinguishable from each other in dark mode (`text-muted-foreground` everywhere).
> **Recommendation**: drop the gradient text fill on the H1 — use the primary color flat, gain ~2:1 contrast. Reserve `text-muted-foreground` for tertiary metadata only.

### Susan Weinschenk — *Cognitive psychology*
> The diff-result Badge flips color (purple → red) at the 95% match threshold (`compare-page.tsx:231`) — a sharp binary at an arbitrary number. Users will get repeated red badges as they iterate, triggering negative affect that doesn't map to actual severity. Color-pulse should track progress (gradient green→amber→red), not snap.
> **Recommendation**: gradient threshold + textual interpretation (`"5 regions need attention"` not just `87%`).

### Erika Hall — *Conversation design / voice*
> Microcopy is functional but voiceless. `t("common.loading")` ("Loading..."), `t("compare.running")` ("Running..."), `t("project.selectFrame")` ("Select a frame") — the system speaks in stage directions, never in the user's frame of reference. Compare with: "Comparing your design with the screenshot…" — same length, infinitely warmer.
> **Recommendation**: full i18n string audit. ErrorBoundary message in particular is bare (`error.message` only — see Part 1 #32).

### Brad Frost — *Atomic design / component reuse*
> Three independent "view-mode toggle" implementations exist: `compare/view-mode-toggle.tsx`, `live-overlay/overlay-view-mode-toggle.tsx`, and inline button groups in `setting-dialog.tsx` (light/dark theme buttons styled identically). All three deserve to be one `ToggleGroup` atom.
> **Recommendation**: extract a `<ToggleGroup>` primitive into `app/desktop/src/component/ui/toggle-group.tsx`, then refactor consumers. Reduces inconsistency surface area for free.

### Cheryl Platz — *Multi-modal / failure handling*
> Failure paths are silent. `compare-page.tsx:158-184` catches `e` and writes `${t("compare.loadFailed")}: ${String(e)}` to error state — string concatenation of an i18n key prefix with raw error text. There is no retry button, no "Open file dialog", no fallback to a different screenshot path. Users hit one error and the only escape is the back button.
> **Recommendation**: every error state needs a "Try again" affordance + the ability to abandon the broken input gracefully. See Part 1 #12 for the error-shape contract.

**Ethics**: No dark patterns. The app is a developer tool, not a conversion funnel — no confirmshaming, no fake scarcity, no pre-checked marketing consent, no roach motel. Settings dialog includes a clean delete-token path. **Clean bill.**

**Usability** (Nielsen H1/H2/H3/H6/H7/H10): Drops 30 points from missing escape on long ops (H3), no progress indicator on compare (H1, H1's Goal-Gradient subcheck), placeholder-as-only-label on screenshot input (H6), no keyboard shortcuts (H7), error messages without recovery action (H10).
